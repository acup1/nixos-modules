# Модуль `sunshine`

* **Экспорт**: `nixos` + `home`
* **Назначение**: Сервер стриминга рабочего стола и игр Sunshine в GNOME, в том числе без подключённого монитора.

## Структура

* `default.nix` — экспортирует обе части: `nixos = import ./nixos.nix;` и `home = import ./home.nix;`.
* `nixos.nix` — подключает `WM-DE/gnome` и `configuration/`.
* `home.nix` — подключает `home_packages/`.
* `configuration/sunshine.nix`:
  * Служба Sunshine с правами захвата KMS.
  * Открытие необходимых UDP/TCP портов в фаерволе.
  * Автологин пользователя в GNOME через GDM.
  * Загрузка драйвера VKMS для виртуального DRM-дисплея `Virtual-1` без HDMI-заглушки.
  * Копия `61-mutter.rules` без правил игнорирования VKMS разрешает Mutter использовать виртуальный дисплей. Остальные аппаратные правила сохраняются.
  * Скрипты `sunshine-client-mode` и `sunshine-default-mode` для изменения разрешения и частоты через Mutter (`gdctl`).
  * Скрипт `sunshine-headless` ожидает готовности GNOME и настраивает виртуальный экран перед каждым запуском Sunshine.
* `configuration/power.nix` — системный запрет сна и гибернации, отключение простоя GNOME и GDM с заблокированными настройками dconf.
* `home_packages/gnome/` — отключение автоматической блокировки в пользовательской сессии.

## Питание

Хост Sunshine не уходит в сон: systemd запрещает suspend, hibernate,
hybrid-sleep и suspend-then-hibernate, а logind игнорирует простой.
Для GNOME и экрана входа GDM системная база dconf отключает гашение
экрана и автоматический сон как от сети, так и от батареи. Эти ключи
заблокированы, поэтому сохранённые пользовательские настройки их не меняют.
Политика входит в системную конфигурацию и не требует отдельного Home Manager switch.

## Виртуальный экран

Базовый режим — `1920x1080@60`, масштаб — 1. При подключении Moonlight
модуль пытается выбрать запрошенный клиентом режим из доступных VKMS.
Если такого разрешения или частоты нет, используется базовый режим.
После отключения клиента базовый режим восстанавливается.

Этот профиль оставляет `Virtual-1` единственным активным выходом GNOME.
Sunshine захватывает его через KMS с `CAP_SYS_ADMIN` (индекс `output_name = 0`);
старые настройки Hyprland и WLR больше не нужны.

Для NVIDIA модуль явно выбирает NVENC и пакет Sunshine без CUDA-пути
захвата. Переменная сессии Mutter
`MUTTER_DEBUG_MULTI_GPU_FORCE_COPY_MODE=primary-gpu-cpu` заставляет GNOME
копировать готовый кадр в собственный буфер VKMS. Без этого GNOME
импортирует буфер рендерящего GPU в VKMS, и программное чтение через
Mesa завершается `GL 0x505`: виден чёрный экран со следами курсора.
Sunshine читает собственный буфер VKMS через Mesa и передаёт кадр NVENC.
Рендеринг GNOME и кодирование остаются аппаратными; копирование и
преобразование кадра используют CPU.

После изменения режима копирования нужна новая сессия GNOME —
перезагрузи хост после системного switch. Перезапуск одного Sunshine
не меняет уже работающий Mutter.

Бинарная ELF-обёртка пакета добавляет `/run/opengl-driver/lib` в путь библиотек
после capability-wrapper NixOS: иначе встроенный FFmpeg не находит
`libcuda.so.1` и Sunshine возвращается к Vulkan. Сам Sunshine при этом
не пересобирается — обёртка использует существующий пакет.
Для остальных драйверов сохраняется автоматический выбор кодировщика.

Порты Sunshine исключены из автоматического назначения исходящим
соединениям через `net.ipv4.ip_local_reserved_ports`. Это защищает UDP
47998–48000, которые Sunshine открывает только при запуске потока.
Если другой модуль задаёт собственный список зарезервированных портов,
в него нужно включить `47984,47989-47990,47998-48000,48002,48010`.
После первого применения этой настройки нужна перезагрузка: она
освобождает уже занятые фоновые сокеты; резервирование действует
на последующие автоматические назначения.

После первого включения GNOME/VKMS или изменения udev-правил нужно
перезагрузить хост: это запускает новую сессию GNOME и заново применяет
правила к DRM-устройствам. Одного перезапуска Sunshine недостаточно,
если Mutter уже пропустил VKMS при старте.

Позднее правило `TAG-="mutter-device-ignore"` не подходит: оно убирает
тег из `CURRENT_TAGS`, но сохраняет его в `TAGS`, которые читает Mutter.
Поэтому модуль удаляет назначающие этот тег VKMS строки из копии
пакетного файла правил и подключает копию после самого пакета Mutter.
